workbuddy-to-dsh：把 WorkBuddy 已登录的模型接入任意 AI 客户端

Ianz2026-10-142026-10-14

它解决什么问题

如果你在用 WorkBuddy 桌面端（或 CodeBuddy），账号里已经登录了一批模型
（DeepSeek、GLM、Kimi、MiniMax、混元……），但只有它自己的客户端能用。

想在 Claude Code、Codex、opencode、Cursor、Cherry Studio 里用同一批模型？
通常的做法是去找 API Key、充值、配一堆环境变量。

workbuddy-to-dsh 换了个思路：把本机桌面端已经登录好的会话，
直接暴露成一个本地 OpenAI / Anthropic 兼容接口。

一句话概括：你在 WorkBuddy 里能用的模型，现在任何支持自定义 Base URL 的客户端都能用。

三个”不需要”

这是我当初做它的主要原因 —— 把上手成本压到接近零：

  • 不需要 API Key —— 复用桌面端已有的登录态，令牌在本机进程内解密，不落盘
  • 不需要 npm install —— 整个项目零依赖，只用 Node 内置模块
  • 不需要改配置 —— 所有项都有合理默认值，.env 完全是可选的

前置条件

项 要求
系统 Windows（桌面端登录文件读取依赖 Windows 路径）
Node.js 18 或更高（开发环境验证于 22.22.2）
WorkBuddy 桌面端 已安装，且登录过一次（登录态是桥的凭据来源）

登录文件位置：%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\。
那里没有 .info 文件的话，先打开 WorkBuddy 登录一次。

第 1 步：跑起来

然后双击根目录的 启动.cmd。就这一步。

它会自动定位 Node.js、启动服务、并在浏览器里打开控制台
（http://127.0.0.1:8792）—— 桥也会被自动拉起，不需要手工操作。

不想开控制台也可以：

第 2 步：把 Base URL 填进你的客户端

桥同时讲三套协议，填哪个地址取决于你的客户端讲哪套：

协议 Base URL 适用客户端
OpenAI 兼容 http://127.0.0.1:8790/v1 Cherry Studio、LobeChat、Cursor、Trae…
Anthropic Messages http://127.0.0.1:8790（不带 /v1） Claude Code
OpenAI Responses http://127.0.0.1:8790/v1 Codex

API Key 一律填控制台「客户端接入」页签给出的本地令牌。

不想手抄配置？

控制台面板最上面有**「一键接入」：它检测本机装了哪些客户端
（Codex / Claude Code / opencode），把 Base URL 与令牌直接写进**它们的配置文件。

安全上做了几件事：只动它自己的键（cc-switch 写过的节一字不动）、
写入前整份备份、支持一键撤销、写完拿配置里的令牌真打一次桥验证。

命令行也可以：

第 3 步（可选）：装进 DeepSeek Harness

只有用 dsh 的人才需要这一步。三种方式装的是同一个插件，任选一种：

装完重启一次 dsh，之后在「设置 → WorkBuddy」里勾选要用的模型，
点「保存到 dsh 设置」，再重启一次 —— 模型就会出现在选择器里。

支持哪些客户端

只要客户端允许填自定义 Base URL，基本都能接：

  • Claude Code —— 走 Anthropic Messages 协议
  • Codex —— 走 Responses 协议（桥内置了协议转换，不用再装中间人）
  • opencode / Cursor / Trae / Cherry Studio / LobeChat / Open WebUI —— 走 OpenAI 兼容协议
  • DeepSeek Harness —— 有原生插件，模型直接出现在选择器里

安全边界

这一点我做得比较克制，因为它是能花你账号额度的东西：

  • 只监听 127.0.0.1 —— 不对外暴露，不绑 0.0.0.0
  • 本地令牌始终必需 —— 未配置时会自动生成随机令牌并打印在启动日志里
    （而不是”没配就放行”）
  • 令牌不落盘、不进日志 —— 桌面端的登录文件从不被回写
  • 可选的分客户端凭据 —— 不同客户端发不同的 key，分开记账与限流，
    某个客户端失控时单独吊销

常见问题

Q：模型列表里没有我想要的模型？
上游目录会随官方上下线变化。GET /v1/models?all=1 看完整列表，
或到控制台「可用模型」里刷新目录。

Q：客户端里显示「上下文 0」？
这不是桥的问题 —— 多数客户端对「自定义 provider」只认自己内置的模型表。
需要在客户端侧显式声明上下文长度，具体位置见项目的
docs/TROUBLESHOOTING.md。

Q：图片发过去模型像没看见？
这类”静默失败”最难查。项目里有一节专门讲怎么三段定位（插件 / 桥 / 上游），
并附带一条可直接粘贴的自查命令。

项目地址

  • GitHub：https://github.com/Ianzhyh/workbuddy-to-dsh
  • 排错文档：仓库里的 docs/TROUBLESHOOTING.md（覆盖 20+ 种真实故障）
